# CCTR Tableau AI Guide

AI Guide will provide a chat panel inside a Tableau dashboard. Phase 1 uses
in-memory mock responses; it does not connect to AWS or collect user identity.

The production hosting bootstrap and hosted development resize diagnostic are
verified. The local `dev` branch now contains the Forge-style chat interface with
mock replies, sources, retry, and New conversation. Desktop chat acceptance is
next; hosted Server acceptance awaits the administrator's safe-list entry.

## Hosting

Production: <https://tableau-chatbot-ui.algo-alert-cramer.workers.dev/>

Development Worker Preview:
<https://dev-tableau-chatbot-ui.algo-alert-cramer.workers.dev/>

The first `dev` publication passed Cloudflare Builds and full HTTP verification
at commit `d907a96` on October 13, 2026. The existing development manifest already
uses the verified stable Preview URL. Hosted Tableau Server acceptance is next.

Use **Cloudflare Workers Builds**, not Pages:

| Setting | Value |
| --- | --- |
| Production branch | `main` |
| Root directory | Repository root |
| Build command | `npm run build` |
| Deploy command | `npx wrangler deploy` |
| Assets directory | `./dist`, configured in `wrangler.jsonc` |

Wrangler is pinned in `package.json` and `package-lock.json`. Cloudflare supplies
the build authentication; credentials do not belong in this repository.

In **Previews Base**, set Build command to `npm run build`, Preview command to
`npx wrangler preview`, Root directory to `/`, and enable preview-branch builds.
The required `previews` block is in `wrangler.jsonc`.

## Local verification

Use Node 22.23.3 (`.nvmrc`) or a supported Node 24 version.

```sh
npm ci
npm test
npm run build
npm run preview
```

In another terminal, verify the locally served diagnostic:

```sh
npm run verify:deploy -- http://localhost:8787/
```

Restart the preview server after rebuilding `dist`. For live editing and the
standalone simulation, use the Vite development server below.

For interactive standalone development:

```sh
npm run dev
```

Open <http://localhost:5173/?standalone=1>. This is an explicit simulation; it does
not prove Tableau integration. Production builds ignore the standalone flag.

Verify the hosted development extension against the published checkout's commit:

```sh
npm run verify:deploy -- https://dev-tableau-chatbot-ui.algo-alert-cramer.workers.dev/
```

You can supply a full expected commit SHA as the second argument. Verification
checks HTML, revision, headers, missing-file behavior, scripts/styles, XML
manifests, environment URLs, and SDK checksum. Use `--bootstrap` when checking the
production stub, which does not yet contain the extension assets.

## Test in Tableau Desktop

The running pilot Desktop is 2025.1, whose Qt webview embeds Chromium 87.
The chat supports this browser: mock copying uses JSON, request IDs fall back
to cryptographic `getRandomValues`, and production assets target Chrome 87.
After a local code fix, collapse the floating extension and Reload it before
retesting; a fresh greeting should enable the composer.

1. Keep `npm run dev` running and open the pilot dashboard in Tableau Desktop.
2. Add an Extension object as **floating**, then choose **Access Local Extensions**
   and select `public/AIGuide.local.trex` generated by the build.
3. Collapse the panel before author positioning. Place it near the upper-right
   corner and set its authored size to approximately **140 × 36**.
4. Open AI Guide, type test text, increment the persistence probe, close, and
   reopen. Confirm both values survive and collapse restores authored geometry.
5. Test a large dashboard and approximately **600 × 400**, plus a dashboard size
   change while open. Close and the test field must remain reachable.

See the [resize acceptance checklist](docs/RESIZE_SPIKE.md). Do not enter patient
or participant information into diagnostic text.

Reload the local extension to try the chat. Use **Demo scenario** for normal,
slow, sources, lost-reply, permanent-failure, reset-failure, and malformed replies.
**Layout test** retains the original diagnostic; **Back to chat** preserves chat
state. Follow the [chat acceptance checklist](docs/CHAT_ACCEPTANCE.md).

Test controls are local by default. To explicitly include them in a hosted `dev`
build, set `AI_GUIDE_TEST_CONTROLS=true` under Cloudflare Previews Base. The build
disables them on `main` even if that variable is set. There is no real backend.

See [deployment instructions](docs/DEPLOYMENT.md) and the
[Phase 1 requirements](docs/PHASE_1_PLAN.md).
